# v0.20 Windows port — status of the three cross-platform TODOs

The macOS fork (v0.20.0-alpha.23) was adopted back into the Windows repo on
branch `port/v0.20-parity`. Three features needed a platform-specific
decision because the mac implementation leaned on macOS-only APIs. Here's
where each landed.

## 1. Onboarding permission walkthrough — FIXED (Windows skips it)

**macOS:** step 4 of onboarding walks the user through granting Accessibility
and Screen Recording via System Settings (TCC), polling until granted.

**Windows:** there is no TCC. Desktop automation, screen capture, and input
synthesis all work with no per-app grant. Running the mac walkthrough on
Windows called the Swift bridge's `permissions` command (unavailable on
win32) → an all-false snapshot → the step polled "Needed" forever with no
way to advance.

**Resolution:** `src/renderer/onboarding.ts` now skips step 4 on Windows.
Step 3 "Meet Clippy" advances straight to step 5 "app picker" via
`showStep(IS_MAC ? 4 : 5)`, and the Back handler mirrors the skip
(`if (!IS_MAC && target === 4) target = 3`). macOS behavior is byte-for-byte
unchanged. Windows onboarding no longer hangs.

## 2. Bubble AX-tree send verification — SAFE NO-OP on Windows (mac-only source)

**macOS:** after a send-style action, the brain reads the accessibility tree
and feeds it to `send-verify.ts` `classifyMessagesTree()` to confirm the
message actually left (vs. the model merely *claiming* "Sent!"). Verdict:
`sent` / `not_sent` / `unknown`.

**Windows:** the *decision core* (`send-verify.ts`) is pure and cross-
platform. Only the AX-tree *data source* is mac-only. On Windows the verdict
stays `unknown`, and the existing honest-copy path already handles that — the
model says "sent (unverified)" rather than falsely asserting confirmation. No
hang, no crash, no false positive.

**Future enhancement (not blocking):** wire a win32 UIA-tree read (via the
existing PowerShell UIA bridge) as the Windows data source so the verdict can
be `sent`/`not_sent` instead of `unknown`. Tracked in `tool-meta.ts` — the
`platforms` field on the send-verify path already anticipates `['win32',
'darwin']` once the UIA read lands.

## 3. Writing assistant (grammar badge) — SAFE NO-OP on Windows (mac-only)

**macOS:** an always-on Harper-linter badge over the focused text field
(⌥G), reading and rewriting via the Swift accessibility bridge
(`a11yFocused` / `a11yFocusedSetValue`).

**Windows:** `src/main/writing-watch.ts` is hard-gated —
`if (this.running || process.platform !== 'darwin') return;` — so it never
starts on Windows. The Harper linter itself (`writing-assist.ts`) is
portable; only the focused-field read/write layer is mac-a11y-bound.

**Future enhancement (not blocking):** reimplement the focused-field
read/write over win32 UIA (TextPattern / ValuePattern via the PowerShell UIA
bridge) and drop the darwin gate. This is the larger of the three (live-
typing UIA polling has real perf considerations) and is deferred rather than
half-built.

## Summary

| TODO | Windows state | Ship-blocking? |
|------|---------------|----------------|
| Permission walkthrough | Skipped (correct — no grants needed) | Was a hang; **now fixed** |
| Bubble AX-verify | `unknown` verdict + honest copy | No — safe no-op |
| Writing assistant | Off (darwin-gated) | No — safe no-op |

Only #1 was a correctness bug; it's fixed. #2 and #3 degrade gracefully and
are genuine future enhancements, not regressions.
